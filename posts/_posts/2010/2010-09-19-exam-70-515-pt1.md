**Focus Point:  Developing Web Forms Pages**

***Configure Web Forms Pages***

A [page directive](http://msdn.microsoft.com/en-us/library/ydy4x04a(VS.100).aspx) is a page-specific attribute used by the ASP.NET page parser and compiler.  Some of these attributes I’ve linked and detailed below:

- [Page.AsyncMode Property](http://msdn.microsoft.com/en-us/library/system.web.ui.page.asyncmode(VS.100).aspx) – Sets a value indicating the page is processed synchronously or asynchronously.  The AsyncMode property is set by the Page parser when code for the page is generated. Use the Async attribute in @ Page directive to set this value.  Asynchronous pages do not work when the AspCompat attribute is set to true or the Transaction attribute is set to a value other than Disabled in the @ Page directive.
- [Page.AsyncTimeout](http://msdn.microsoft.com/en-us/library/system.web.ui.page.asynctimeout(VS.100).aspx) Property – Gets or sets a value indicating the time-out interval used when processing asynchronous tasks.  The asynchronous time-out of the page represents the amount of time that the page will wait to perform asynchronous tasks. In most circumstances, do not set this property in code. Set the page asynchronous time-out interval using the pages element of the Web configuration file or in the @ Page directive. Values set in the page configuration section are overwritten by the page directive.  Define your asynchronous task using the PageAsyncTask class and register a beginning, an ending, and a time-out handler. If the asynchronous task does not complete in the time interval specified, the time-out handler will be invoked.
- [Page.AspCompatMode Property](http://msdn.microsoft.com/en-us/library/system.web.ui.page.aspcompatmode(VS.100).aspx) – Sets a value indicating whether the page can be executed on a single-threaded apartment (STA) thread.  This allows the page to call STA components, such as components developed with Visual Basic 6.0. Setting this property to true also allows the page to call COM+ components that require access to the unmanaged ASP built-in objects. These are accessible through the ASP ObjectContext object or the OnStartPage method.  In most circumstances, do not set this property in code. Set the aspcompat attribute to true using the @ Page directive in the .aspx file. When the page is requested, the dynamically generated class sets the property.
- [Page.Buffer Property](http://msdn.microsoft.com/en-us/library/system.web.ui.page.buffer(VS.100).aspx) – Sets a value indicating whether the page output is buffered.  In most circumstances, do not set this property in code. Set the Buffer attribute to true using the @ Page directive in the .aspx file. When the page is requested, the dynamically generated class sets the property.
- [Control.ClientIDMode Property](http://msdn.microsoft.com/en-us/library/system.web.ui.control.clientidmode(VS.100).aspx) – Gets or sets the algorithm that is used to generate the value of the ClientID property.  The values are [AutoID](http://msdn.microsoft.com/en-us/library/system.web.ui.clientidmode.aspx) which generates the value by concatenating the ID values of each parent naming container with the ID value of the control, seperated by an underscore character.  The [Static](http://msdn.microsoft.com/en-us/library/system.web.ui.clientidmode.aspx) value sets the value statically and makes the control the top of the hierarchy of naming containers if it is a container.  [Predictable](http://msdn.microsoft.com/en-us/library/system.web.ui.clientidmode.aspx) algorithm is used for controls that are data-bound controls and concatenates the ClientID value of the parent with the ID value of the control.  [Inherit](http://msdn.microsoft.com/en-us/library/system.web.ui.clientidmode.aspx) sets it to the parent control.
- [Page.ClientTarget Property](http://msdn.microsoft.com/en-us/library/system.web.ui.page.clienttarget(VS.100).aspx) – Gets or sets a value that allows you to override automatic detection of browser capabilities and to specify how a page is rendered for particular browser clients.  If you do not set the ClientTarget property, the HttpBrowserCapabilities object associated with the Page.Request property reflects the browser capabilities associated with the value (alias) that you provide.  uplevel, which specifies
- [CompilationMode Enumeration](http://msdn.microsoft.com/en-us/library/system.web.ui.compilationmode(VS.100).aspx) – Defines constants that specify how ASP.NET should compile .aspx pages and .ascx controls.  Members include; Auto sets ASP.NET to not compile the page if possible, Never states the page will not be dynamically compiled, and Always sets ASP.NET to compile every time.
- [Control.EnableViewState Property](http://msdn.microsoft.com/en-us/library/system.web.ui.control.enableviewstate(VS.100).aspx) – This one has been the disdain of many serious web developers, as the view state becomes a horrifying beast to deal with.  But I digress, it may appear on the test so know about it.  🙂  This property gets or sets a value indicating whether the server control persists its view state, and the view state of any child controls it contains, to the requesting client.
- [Page.EnableViewStateMac Property](http://msdn.microsoft.com/en-us/library/system.web.ui.page.enableviewstatemac(VS.100).aspx) – Gets or sets a value indicating whether ASP.NET should check message authentication codes (MAC) in the page’s view state when the page is posted back from the client.
- [Page.ErrorPage Property](http://msdn.microsoft.com/en-us/library/system.web.ui.page.errorpage(VS.100).aspx) – Gets or sets the error page to which the requesting browser is redirected in the event of an unhandled page exception.
- [Page.MasterPageFile Property](http://msdn.microsoft.com/en-us/library/system.web.ui.page.masterpagefile(VS.100).aspx) – Gets or sets the file name of the master page.
- [Page.MetaDescription](http://msdn.microsoft.com/en-us/library/system.web.ui.page.metadescription(VS.100).aspx) – Gets or sets the content of the “description” meta element.
- [Page.MetaKeywords](http://msdn.microsoft.com/en-us/library/system.web.ui.page.metakeywords(VS.100).aspx) – Gets or set the content of the “keywords” meta element.
- [Page.Theme Property](http://msdn.microsoft.com/en-us/library/system.web.ui.page.theme(VS.100).aspx) – Gets or sets the name of the page theme.
- ViewStateEncryptionMode Enumberation – Specifies whether view-state information is encrypted;  Auto sets the encryption by calling the [RegisterRequiresViewStateEncryption](http://msdn.microsoft.com/en-us/library/system.web.ui.page.registerrequiresviewstateencryption.aspx) method, Always sets it to encrypt always and Never does not encrypt even if the control requests it.
- [Control.ViewState Property](http://msdn.microsoft.com/en-us/library/system.web.ui.control.viewstatemode(VS.100).aspx) – Gets or sets the view-state mode of this control.
- [Control.ViewStateMode Property](http://msdn.microsoft.com/en-us/library/system.web.ui.control.viewstatemode(VS.100).aspx) – Gets or sets the view-state mode of this control.
- [Compiler.WarningLevel Property](http://msdn.microsoft.com/en-us/library/system.web.configuration.compiler.warninglevel(VS.100).aspx) – Gets the compiler warning level.
- Saving and reading values in View State:  [Save Values](http://msdn.microsoft.com/en-us/library/ms227551(v=VS.85).aspx) / [Read Values](http://msdn.microsoft.com/en-us/library/ms228048(v=VS.85).aspx)
- Auto Event Wire Up – i.e. [ASP.NET Web Server Control Event Model](http://msdn.microsoft.com/en-us/library/y3bwdsh3(VS.100).aspx).
- [PageSection.EnableEventValidation](http://msdn.microsoft.com/en-us/library/system.web.configuration.pagessection.enableeventvalidation.aspx) Property – Gets or sets a value that specifies whether event validation is enabled.
- General configuration settings (ASP.NET) – This topic covers web.config files and setting up configuration sections within this file.  Some of the topics to be familiar with include; [connectionStrings](http://msdn.microsoft.com/en-us/library/bf7sd233.aspx), [system.web](http://msdn.microsoft.com/en-us/library/dayb112d.aspx), [configSections](http://msdn.microsoft.com/en-us/library/ms228256.aspx), [appSettings](http://msdn.microsoft.com/en-us/library/ms228154.aspx), [location](http://msdn.microsoft.com/en-us/library/b6x6shw7.aspx), [System.Configuation](http://msdn.microsoft.com/en-us/library/system.configuration.aspx), and [System.Web.Configuration](http://msdn.microsoft.com/en-us/library/system.web.configuration.aspx).
- [XHTML Standards in Visual Studio and ASP.NET](http://msdn.microsoft.com/en-us/library/exc57y7e(VS.100).aspx)
- [Editing ASP.NET Configuration Files](http://msdn.microsoft.com/en-us/library/ackhksh7(VS.100).aspx) – Case-sensitivity, custom sections, remote configuration files, etc.
- Making controls easier to access via JavaScript since they’re often cryptic…  [Walkthrough:  Making Controls Located in Web User Controls Easier to Access from JavaScript](http://msdn.microsoft.com/en-us/library/dd483476(VS.100).aspx), [How to:  Access Controls from JavaScript by ID](http://msdn.microsoft.com/en-us/library/dd410598(VS.100).aspx), and [Walklthrough:  Making Data-Bound Controls Easier to Access from JavaScript](http://msdn.microsoft.com/en-us/library/dd381611(VS.100).aspx).

**Implement Master Pages and Themes**

- [ASP.NET Themes and Skins](http://msdn.microsoft.com/en-us/library/ykzx33wh(VS.100).aspx) – A theme is a collection of property settings that allow you to define the look of pages and controls, and then apply the look consistently across pages in a Web Application, across an entire Web Application, or across all Web Applications on a server.  A [Theme and Control Skins](http://msdn.microsoft.com/en-us/library/ykzx33wh(VS.100).aspx#ThemesAndControlSkins) are setup using CSS (Cascading Style Sheets) and other elements based on the page or individual controls.
- [Themes vs. Cascading Style Sheets](http://msdn.microsoft.com/en-us/library/ykzx33wh(VS.100).aspx#ThemesVsCascadingStyleSheets) – Themes are similar to cascading style sheets, and can even use CSS, themes go one step further an enable skinning individual complex controls such as treeviews.
- [Control.SkinID Property](http://msdn.microsoft.com/en-us/library/system.web.ui.control.skinid(VS.100).aspx) – Gets or sets the skin to apply to the control.
- [Passing information between content and master pages](http://www.4guysfromrolla.com/articles/013107-1.aspx) – 4GuysFromRolla site link.  These guys, from way way back when I started programming have always had some seriously great content.

**Implement Globalization**

**Handle Page Life Cycle Events**

- [Page.IsPostBack Property](http://msdn.microsoft.com/en-us/library/system.web.ui.page.ispostback(VS.100).aspx) – Gets a value that indicates whether the page is being rendered for the first time or is being loaded in response to a postback.  For an explanation of the difference between postbacks and callbacks, see [Implementing Client Callbacks Programmatically Without Postbacks in ASP.NET Web Pages](http://msdn.microsoft.com/en-us/library/ms178208.aspx).  Also see the [How-To:  Determine How ASP.NET Web Pages Were Invoked](http://msdn.microsoft.com/en-us/library/ms178141(en-us,VS.100).aspx).
- [Page.IsValid Property](http://msdn.microsoft.com/en-us/library/system.web.ui.page.isvalid(VS.100).aspx) – Gets a value indicating whether page validation succeeded.  For this property to return true, all validation server controls in the current validation group must validate successfully.  Check this property only after calling the [Page.Validate](http://msdn.microsoft.com/en-us/library/system.web.ui.page.validate.aspx) method, or set the CausesValidation property to true on the OnServerClicke event handler of the ASP.NET Server control that initiates form processing.  Also be aware of how to [disable validation](http://msdn.microsoft.com/en-us/library/bt244wbb(en-us,VS.100).aspx) or [display server side custom validation messages for ASP.NET server controls](http://msdn.microsoft.com/en-us/library/3w0bs977(en-us,VS.100).aspx).
- [ASP.NET Page Life Cycle Overview](http://msdn.microsoft.com/en-us/library/ms178472(VS.100).aspx), and also check out the [How-to:   Add Controls to an ASP.NET Web Page Programmatically](http://msdn.microsoft.com/en-us/library/kyt0fzt1(VS.100).aspx).
- Be sure to review these events that can be overridden;  [Page.PreInit Event](http://msdn.microsoft.com/en-us/library/system.web.ui.page.preinit(VS.100).aspx), [Control.Init Event](http://msdn.microsoft.com/en-us/library/system.web.ui.control.init(VS.100).aspx), [Page.InitComplete Event](http://msdn.microsoft.com/en-us/library/system.web.ui.page.initcomplete(VS.100).aspx), [Page.PreLoad Event](http://msdn.microsoft.com/en-us/library/system.web.ui.page.preload(VS.100).aspx), [Control.Load Event](http://msdn.microsoft.com/en-us/library/system.web.ui.control.load(VS.100).aspx), [Page.LoadComplete Event](http://msdn.microsoft.com/en-us/library/system.web.ui.page.loadcomplete(VS.100).aspx), [Control.PreRender Event](http://msdn.microsoft.com/en-us/library/system.web.ui.control.prerender(VS.100).aspx), [Page.PreRenderComplete Event](http://msdn.microsoft.com/en-us/library/system.web.ui.page.prerendercomplete(VS.100).aspx), [Page.SaveStateComplete Event](http://msdn.microsoft.com/en-us/library/system.web.ui.page.savestatecomplete(VS.100).aspx), [Control.Render Method](http://msdn.microsoft.com/en-us/library/system.web.ui.control.render(VS.100).aspx), and the [Control.Unload Event](http://msdn.microsoft.com/en-us/library/system.web.ui.control.unload(VS.100).aspx).

**Implement Caching**

- [ASP.NET has a caching mechanism](http://msdn.microsoft.com/en-us/library/6hbbsfk6(VS.100).aspx) that allows storage of objects in memory.  This caching is implemented by the [Cache Class](http://msdn.microsoft.com/en-us/library/system.web.caching.cache.aspx).  The primary two functionalities of the cache are to [add items to the cache](http://msdn.microsoft.com/en-us/library/18c1wd61.aspx) and to [retrieve values of cached items](http://msdn.microsoft.com/en-us/library/xhy3h9f9.aspx).  Also you can [delete an item if necessary](http://msdn.microsoft.com/en-us/library/edfcywt6.aspx).
- [Caching ASP.NET Pages](http://msdn.microsoft.com/en-us/library/06bh14hk(VS.100).aspx) – There is a way with ASP.NET that caches actual page requests.  [Setting the Cacheability of a Page](http://msdn.microsoft.com/en-us/library/w9s3a17d.aspx) must be set.  [Multiple Versions of a Page](http://msdn.microsoft.com/en-us/library/xadzbzd6.aspx) can also be cached.  On a more discrete level parts of a page can be cached.  Read [Caching Portions of an ASP.NET Page](http://msdn.microsoft.com/en-us/library/h30h475z(VS.100).aspx) for more information.
- For a thorough overview of [ASP.NET Caching](http://msdn.microsoft.com/en-us/library/ms178597(VS.100).aspx), read the <http://msdn.microsoft.com/en-us/library/ms178597(VS.100).aspx> on the topic.
- Other topics under this item to review are;  [AggregateCacheDependency Class](http://msdn.microsoft.com/en-us/library/system.web.caching.aggregatecachedependency(VS.100).aspx), [Caching in ASP.NET with the SqlCacheDependency Class](http://msdn.microsoft.com/en-us/library/ms178604(VS.100).aspx), and [How to:  Cache Page Output with File Dependencies](http://msdn.microsoft.com/en-us/library/67z4z916(VS.100).aspx).
